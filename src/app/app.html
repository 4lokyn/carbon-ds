Carbon tokens, our components

No carbon-components-angular anywhere. The design language comes from @carbon/styles as Sass; behavior comes from @angular/aria and @angular/cdk; the markup and the class names are ours. Change the theme under the gear in the header — nothing recompiles, only the data-theme attribute on <html> changes.

Grid

Carbon's 2x grid: 16 columns from lg up, 8 on md, 4 on sm. The column count changing is the whole idea — nine-am-col-span-8 is half the page on a laptop and the entire width of a tablet, from one class.

Resize the window and watch the row below re-flow. The gutter is padding on the columns rather than gap, which is Carbon's choice: a gap would leave visible stripes between filled columns, where padding lets a column's background run edge to edge and insets only its content.

Active route

The last three side nav links are real routes. Click one and watch the highlight follow the URL — nothing here binds it. `routerLinkActive` with `ariaCurrentWhenActive` writes aria-current="page", and the shell styles against that attribute, which is what Carbon keys off too.

Button

An attribute on a native <button>. Every color reads from a $button-* component token, which is why all four themes work without a single per-theme override.

Tab to a button, or click one, to see the focus ring — it is inset by 2px so it never shifts layout. It stays until focus moves on, because Carbon writes every focus style against :focus: the ring says where focus is, not how it got there.

Input

The label belongs to the control, not to a wrapper — that is Carbon's own API shape and it keeps every field one element deep. Helper text and the error line share one slot: the error replaces the helper rather than stacking under it, so nothing below shifts when a field goes invalid.

@for (size of fieldSizes; track size) { }

Invalid and warn. Only invalid draws a border — Carbon carries warn on the icon and the message alone, because $support-warning is the same yellow in all four themes and yellow text fails contrast on the light ones. Focus an invalid field: the blue ring wins while you are in it, and the red comes back on blur, which is also when validation runs.

Password, disabled and read-only. The reveal toggle is an icon-only control, so its name is an input rather than a hardcoded string.

The fluid variant. Not a fourth size — the label moves inside a fixed 64px box, so it is a different layout rather than a taller one. Helper text has nowhere to go and is dropped; the error message moves inside the box, below a divider.

Select

A native <select> with the arrow drawn over it, because a native arrow cannot be styled. Options are projected rather than configured — <nine-am-select><option> — which keeps <optgroup>, disabled options and an empty placeholder row working without re-exposing any of them.

@for (size of fieldSizes; track size) { }

Read-only deserves a footnote: a native <select> has no readonly, so readOnly sets disabled underneath and puts the look back. The consequence is that a read-only select is not submitted with its form — send the value yourself.

Textarea

No size scale — Carbon sizes a textarea with rows, not with the 32/40/48 field heights. The type style is body-01 rather than the compact one every single-line field uses: compact line height reads fine on one line and cramped the moment text wraps. Drag the bottom-right corner — vertical resize only.

One deliberate deviation from Carbon here: Carbon reserves no right-hand gutter for the status icon, so the first line of text runs underneath it. We reserve it. An icon that hides the value it is complaining about is worse than a field 40px narrower.

Radio group

Almost none of this is ours. Give native radios a shared name and the browser supplies single selection, arrow-key navigation, and a tab order where the whole group is one stop rather than one per option — try it: Tab in, then arrow between them, then Tab out. The <fieldset> is doing work too: its disabled cascades to every input inside, and the <legend> is what names the group to a screen reader.

Read-only is the one place the browser fights us. A radio has no native readonly, and by the time change fires the browser has already checked one option and unchecked another — which a single input cannot undo. So it is cancelled on the click instead, before any of it happens. Tab into the read-only group and press an arrow: focus moves, the selection does not.

Checkbox group

A group, unlike a radio group, owns no value. Each box keeps its own checked; what the group owns is the legend, the message, disabled and readOnly — the things the set genuinely shares.

Untick all three and the group goes invalid. Note that the message appears once, not once per box — the boxes point their aria-describedby at the group's single message, so a screen reader hears the requirement one time however long the list is.

A lone checkbox carries its own message instead — the standalone case Carbon keeps invalid on the checkbox for.

Toggle

A <button role="switch">, not a checkbox — Carbon's choice and the right one. A switch takes effect immediately; a checkbox is a value you submit later, and screen readers announce the two differently. checked is a model(), so this already satisfies FormCheckboxControl with no adapter.

The check inside the switch appears on the small size only. It is positioned for a 16px track, and at 24px the knob is large enough to read on its own — which is why Carbon draws it in exactly one of the two.

Date picker

The one component here built on a third-party primitive. @angular/aria has no calendar, so the month grid, the roving focus and the arrow / Home / End / PageUp / PageDown keys come from ng-primitives; the markup, the class names and every pixel are ours. Same split as Tabs, different vendor. The popover is CDK Overlay, not the primitive's own — we already use the CDK for Modal, and taking theirs would have meant a second positioning engine in the bundle.

Open one and use the keyboard: arrows move a day, PageUp / PageDown move a month, Home / End jump to the ends of the week, Enter picks, Escape closes and puts focus back in the field. None of that is our code.

The field is typeable, and the default format is ISO yyyy-mm-dd — deliberately not a locale format. Whatever the field shows has to be something the field can read back, and 03/04 is two different days depending on who is reading it. formatDate and parseDate are both inputs; override them together, never one alone.

Range

One field holding both ends, one calendar. Click a start day, then an end day: the calendar closes on the second, because the primitive reports the two as separate events and closing on the first would make the second impossible. Carbon renders a range as two fields — this is deliberately one.

A single field has to read its own separator back, so the parser accepts an en dash, an em dash, a spaced hyphen or the word to. All of them require surrounding whitespace, which is what stops them colliding with the hyphens inside an ISO date — 2026-08-13-2026-08-15 has no unambiguous split point, 2026-08-13 – 2026-08-15 does.

The panel here is the same component the single picker uses. ng-primitives' grid directives resolve their state through a fallback, so the markup does not care which of the two picker directives sits above it.

Multi-select

Carbon's MultiSelect: a count in the field, a listbox of checkboxes below it. ng-primitives owns selection, roving focus and the keyboard; the field, the popover and the class names are ours. The rows reuse nine-am-checkbox, which already does indeterminate — which is exactly what a partial select-all needs.

Options are configured here rather than projected, the opposite of nine-am-select, and for a concrete reason: select-all has to know the whole set and the filter has to know each row's text. Projected <option> elements expose neither.

Type in the filterable one, then press Select all. It applies to the rows the filter left, not to the hundred it is hiding — and clearing it does not drop them either. That is the part implementations usually get wrong.

When invalid appears

Carbon specifies the timing, not just the look, and this is it — one rule for the whole app. Type a bad address: nothing happens. Tab away: it turns red. Fix it: the error clears as you type, without waiting for another blur. Press Create with the field untouched and it validates anyway.

The control has no part in this. invalid is a plain input and the policy lives here, in the form — a control cannot see a submit it is not part of.

@if (submitFailed()) {
}
@if (submitted() && !emailInvalid() && !submitFailed()) { submitted with: {{ email() }} }

Submit a valid address twice: the second one comes back as a server error. Note that the field's own message is untouched — the two say different things, and Carbon asks for both rather than one instead of the other.

Data table

Columns are described as data, not as templates — a text column is one line. Sorting is tri-state (click a header three times to get back to unsorted), empty cells stay last in both directions, and CPU / Updated show one thing while sorting on another. Selection is keyed by row id, so it survives sorting, filtering and paging.

Try: sort by Updated — the order follows the real timestamp, not the string. Sort by CPU — the stopped services with no reading sink to the bottom either way. Select rows, then page or sort, and the selection count holds.

Tabs

Behavior is @angular/aria. Focus the tab strip and use ← → Home End — roving tabindex, aria-selected and inert on hidden panels all come from the primitive. We wrote none of it.

  • Roving tabindex — only the active tab is in the tab order
  • Arrow keys, Home and End move between tabs
  • role, aria-selected, aria-controls
  • inert on hidden panels, so they leave the a11y tree
  • $border-interactive — the 2px selected underline
  • $text-secondary / $text-primary — unselected vs selected
  • $background-hover, $text-disabled
  • type-style('heading-compact-01') for the selected weight
  • The markup — which element carries which class
  • The public API: nineAmTab, nineAmTabPanel, and only the inputs we chose to re-expose
  • Selected state read straight off Aria's selected() signal, so there is no second copy of that state to drift

Overflow menu

Roving focus, arrow keys, Home and End, type-ahead, Escape, and focus back to the trigger — all of it ours. It was @angular/aria/menu until that turned out not to work through <ng-content>: Aria collects its items with a content query, projected items belong to the caller's template, and it was quietly managing an empty list. Tab to the three dots and press ArrowDown, or open one and type "d": it jumps to Delete.

last action: {{ lastAction() || 'none' }}

Every item is a real <button>, so Enter and Space work with no help from us. The destructive one goes red on hover and focus rather than at rest — a menu with a permanently red row pulls the eye straight to the thing you least want clicked.

Like the toggletip, the panel is inline rather than in an overlay. So it does not flip at a viewport edge and an ancestor with overflow: hidden will clip it — the same limitation Carbon has, which they answer with a data-floating-menu-container escape hatch.

Menu button and combo button

Carbon documents these and the overflow menu above as one component, "menu buttons", and here they are one too: all three extend MenuSurface, which owns the roving focus, the arrows, Home and End, type-ahead, Escape and the focus return. They differ only in what the user presses to get there.

last action: {{ menuAction() || 'none' }}

The combo button is two controls and two tab stops, which is Carbon's accessibility spec rather than a shortcut: the primary action has to be reachable without opening anything, and one control cannot both do a thing and offer a list of other things. Carbon also allows any button kind on a menu button and only a primary one on a combo button, so there is no kind here to get wrong.

    Tooltip

    An attribute, because a tooltip is something a control has rather than something that wraps it. Hover or Tab to any of these. It is wired as aria-describedby, never aria-labelledby — an icon-only button still needs its own aria-label, because a name that only exists on hover is not a name.

    The caret follows the panel. Push the window narrow enough that the Right one has no room and the CDK flips it — the caret moves to the other side with it, because a caret that keeps pointing at where the trigger used to be is worse than no caret.

    Toggletip

    Carbon draws the line clearly: a tooltip is hover or focus and never interactive; a toggletip is click or Enter and exists so that something inside it can be operated. Open one and press Tab — focus goes into the panel, not past it.

    Link

    An attribute on a native <a>, the same trade the button makes — real navigation, middle-click, the target in the status bar, and announced as a link. None of that survives on a <span>.

    Small Default Large With an icon Visited style on Disabled

    The decision worth making is standalone versus inline. Those above are standalone — underlined only on hover, because nothing around them competes for the eye. In a sentence it is the other way round: this link is underlined at rest, because colour alone is not a reliable signal that something is clickable, and for a colour-blind reader it is no signal at all.

    Disabled keeps the <a> and marks it aria-disabled rather than swapping it for a <p> the way Carbon React does — a paragraph is not in the accessibility tree as a link at all, so a screen reader user is never told the thing exists. Tab to it and it still announces, as unavailable.

    Loading

    The ring is two circles: a faint track and the arc that travels around it. An arc on its own reads as a broken circle rather than as progress. Both sizes below — 88px and 16px.

    Stopping is two turns rather than a freeze: the ring finishes its rotation while the arc closes into a full circle. A spinner that stops mid-turn reads as a crash.

    Callout

    The fourth variant, and the quiet one. A callout loads with the page and cannot be dismissed, so it has no close button, no timeout and no live region — announcing it would interrupt a screen reader that is already reading the page it belongs to.
